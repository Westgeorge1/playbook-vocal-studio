PLAYBOOK VOCAL STUDIO 0.25.0 — CHANGES (from 0.24.0; review REVIEW-0.24.0.txt)

WHAT YOU WILL NOTICE
- Every vocal lane can now be polished. A 4-minute lead plus two 4-minute backing vocals (with phrase fixes)
  all complete POLISH, keep their own edits, play together, export as processed stems or a mix, and reopen.
- "POLISH: 2 of 3 vocals ready" next to Room on the Song screen, and "Whole song: …" in the POLISH bar
  (hover/tap for each lane's state: polished, needs update, key update, dry, or needs your choice).
- If a vocal is too long for POLISH, you are told at once (well under a second); the vocal you are editing stays open.
- A stereo vocal keeps both channels when you reopen it. For stereo longer than 3 minutes (48 kHz) POLISH asks
  whether to polish a mono version, with a "Listen to mono version" button; your stereo recording is kept.
  The choice is shown in the POLISH bar and can be changed in the track settings.
- "Keep this vocal in its own key" now works both ways: changing that vocal's key in POLISH changes only that
  vocal; the song key and other lanes stay. Turning it off adopts the song key.
- POLISH key, scale, Use dry vocal and own-key settings survive an immediate crash/close.
- Songs below 22,050 Hz: POLISH explains it cannot process them (recording, playback and dry export still work).
- Back up project now makes a MODERN backup (no extra copies for older versions; smaller). Export song >
  Modern backups store finished POLISH audio as 16-bit WAV (float only if it peaks above full scale);
  measured 15-min, 3-lane song: modern 218 MiB vs compatibility 651 MiB (0.24.0 backup of the same song: 486 MiB before this change).
  The Compatibility backup keeps 32-bit float everywhere.
  "Compatibility backup" makes the larger one that 0.18.3 can read (lead and parts only).

UNDER THE HOOD (each rule is enforced by tests-0.25/check25.cjs and the tests named in AGENT-HANDOVER.md)
- R1 POLISH capacity is per lane (SongCore.polishPlan), checked before anything else; the shared cross-lane
  256 MB budget is gone. Lane POLISH audio is written to browser storage once (own entries), not on every autosave.
- R2 restoreSession never averages channels; a lane's saved POLISH input must have the lane's channel count
  (or 1 by the explicit track.polishMono choice) to be valid.
- R3 normalizeSigs has no tolerance zone: a legacy POLISH input is accepted only if it equals, sample for sample,
  the current render or the exact 0.20–0.23 render of the current choices.
- R4 one key function (SongCore.wantedKey) for the editor, sync and staleness; only setKey writes the song key.
- R5 one settings path (commitSetting / setPolishPref / setTrackMono); the journal carries POLISH preferences.
- R6 one PCM boundary (SongCore.acceptPcm) used by acceptPolish and by every WAV writer; polishValid requires
  finite audio; peak() reports NaN as infinite. Measured: the unchanged engine produces NaN at 8/11.025/16 kHz.
- Engine files unchanged (ENGINE-SHA256.txt).
