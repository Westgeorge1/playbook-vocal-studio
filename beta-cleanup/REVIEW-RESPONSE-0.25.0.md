# Review response — Playbook Vocal Studio 0.25.0 (to REVIEW-0.24.0.txt)

Approach: remove each bug *class* in code, enforce it with an automatic check, keep prose minimal.
`tests-0.25/check25.cjs` (static invariants) runs first in `run_all25.sh`.

| Finding | Structural fix | Enforcing test(s) |
|---|---|---|
| **R1** full song cannot finish POLISH | The shared cross-lane 256 MB budget is removed. Capacity is a property of ONE lane: `SongCore.polishPlan(w,t)` (input + final of that lane ≤ 256 MB, stereo ≤ 3 min @48 kHz, rate ≥ 22.05 kHz). `open()` calls it **first**, before stopping playback, capturing or touching the engine, so a refusal is instant and the open editor is untouched. Only the active lane is in the engine; completed lanes' POLISH audio is written to IndexedDB once as its own entries (`pcm:`), not rewritten by each autosave. `SongCore.readiness(w)` drives "POLISH: n of m vocals ready" (Song screen) and "Whole song: …" (POLISH bar). | check25 (plan-before-engine, no shared budget); core25 R1; capacity25: 4-min lead + two 4-min backing + 3 min fixes all POLISH (61/67/72 s), separate edits, play together, processed stems + mix finite, reload, modern & compat ZIP reopen; refusal 0.1 ms with editor preserved |
| **R2** long stereo silently mono on reopen | `restoreSession` no longer averages channels (refuses instead, saved sound kept). Mono is only the lane setting `track.polishMono`, chosen in a dialog with "Listen to mono version" or in track settings, shown in the POLISH bar; originals untouched. `polishValid` requires the saved input's channel count to equal the lane's (or 1 when mono was chosen), so a silently converted input can never be approved. | check25 R2; core25 R2; stereo25: 181 s stereo (different tones and opposite polarity) autosave/reload, editor reopen and ZIP round trip keep 2 channels and identical input/final hashes; 190 s 48 kHz stereo asks first; decline = nothing processed |
| **R3** migration approves wrong take near a join | The boundary-zone exception is deleted. A legacy input is accepted only if it equals, sample for sample, the current render or the exact 0.20–0.23 renderer (`renderTrackLegacy23`) applied to the *current* choices; otherwise `stale:`. | check25 R3; core25: the review's script verbatim (now `false`, 0.6/0.6), 10/20 ms fade-in/out at the join, save+reopen stays stale, unchanged legacy and current renders stay valid, one changed seam sample is stale |
| **R4** own key inconsistent | One function, `SongCore.wantedKey(w,t)`, defines the key a vocal must have. The editor shows `editorKey()` (bound lane's wanted key); editor changes go to `keyFromEditor` (own-key lane → only that lane; else `setKey`). Only `setKey` writes the song key. Turning the override off drops the lane's own key, so it adopts the song key and is marked for a safe update. | check25 R4; core25 R4; durable25: UI track settings → own key, song key change, open/edit/switch/switch back/reload, override off, reopen |
| **R5** POLISH settings lost on immediate crash | One durable settings path `commitSetting` (revision + autosave + journal); `setPolishPref` / `setTrackMono` use it; the POLISH bar and track settings use them. The journal carries `polishPrefs` (bypass, ownKey, key, scale), validated and merged onto the saved POLISH object only for the same song uid and a newer revision. | check25 (no `persist()` in change/input handlers; revision only bumped in commitSetting/changed; journal carries prefs); durable25: crash right after POLISH key, scale, dry (track settings), dry (POLISH bar), own-key flag, own key value; foreign journal ignored |
| **R6** NaN passes validation/export | One PCM boundary `SongCore.acceptPcm` (finite only). `acceptPolish` is the only way a lane's processing is replaced and calls it; `polishValid` requires finite audio; `peak()` reports NaN as Infinity; every WAV writer (`wavFloat`, `wav24ch`, `wavSource`) calls it. Measured source: the **engine** returns NaN for sessions at 8, 11.025 and 16 kHz (finite from 22.05 kHz). The engine is byte-locked, so the guard is outside it: `polishPlan` refuses POLISH below 22.05 kHz with a clear message; such projects still record, play and export dry. | check25 R6 (only three WAV writers, all validated; no other writer); core25 R6; stereo25: 8 kHz different/opposite stereo refused instantly, dry mix finite; 44.1/48 kHz finite and valid; NaN/±Infinity results rejected with last good kept; export guard + WAV writer refuse NaN |
